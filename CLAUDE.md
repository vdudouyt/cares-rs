# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

A Rust rewrite of the [c-ares](https://c-ares.org/) asynchronous DNS resolver, shipped as a drop-in `libcares_rs.so` with the c-ares **1.34.6** C ABI. `ares_version()` returns `"1.34.6"`; the authoritative header is `tests/cares-tests/src/include/cares/ares.h` (the dev box's `/usr/include/ares.h` is 1.27-era — do not use it).

## Rules

* Use non-blocking I/O following the reactor pattern. Never use blocking I/O requests.
* All functions and structures exported in C must be `pub`.
* **No thread-local (or global mutable) state.** Working state lives in structures owned — directly or transitively — by the channel (`ChannelData`); e.g. the receive scratch buffer is a field of the channel's `Reactor`, not a `thread_local!`. **Exception: random numbers** — use `rand::thread_rng()`. Its state never influences a result (any draw is just "a random value"), so it cannot leak behavior between channels or threads, and it is a reseeding CSPRNG that rand reseeds after `fork()`. Do not add channel-owned RNGs.
* **No panic paths in production code** — a panic in a C-ABI library aborts the host process. No `panic!`/`todo!`/`unimplemented!`/`unreachable!`/`.unwrap()`/`.expect()` outside `cfg(test)`; degrade gracefully (error status, fallback value, or skip) even for invariants that "can't" fail. Enforced by the deny wall in `src/lib.rs` (fires under clippy, which CI runs with `-D warnings`). For C-string constants use native `c"..."` literals (`c"...".as_ptr()`) — an interior NUL is rejected by the compiler itself, so no conversion or panic machinery is ever involved.
* Commit with **zero** build/clippy warnings.
* **Porting tests:** copy `.c`/`.cc` files from the original c-ares tree at `/root/c-ares-1.34.6/` with as few changes as possible, for logical consistency and easy updates. Copy them verbatim; the only tests you may comment out or skip are malloc/alloc-failure ones.

## Build, lint, test

```bash
cargo build --release            # produces target/release/libcares_rs.so (+ include/cares.h via cbindgen)
cargo clippy --all-targets        # must be warning-clean before committing
cargo test                        # Rust-side integration tests (tests/*.rs)
cargo test --test miri_memory     # the FFI alloc/free + parsing matrix
```

The canonical behavior suite is the **original c-ares C++ gtest binary**, run against the `.so` via `dlsym`:

```bash
cd tests/cares-tests && cmake . && make
./arestest ../../target/release/libcares_rs.so \
  # no filter: the restored 734-test oracle is the CI suite
```

- Run one test: append `--gtest_filter=Foo.Bar` (single filter; the CI filter above is the exclusion set).
- `Live*` tests need real network (the box has it); everything else is mocked.
- Remaining excluded categories are alloc-failure/container/internal tests; EDNS/cookie/DNS0x20/MaxQueries/StayOpen/event-thread behavior is implemented and runs in CI.
- Fuzz corpora: `./aresfuzz <so> fuzzinput/*` (DNS parsing) and `./aresfuzzname <so> fuzznames/*` (server CSV).

CI additionally runs the gtest suite under **Valgrind** (`--leak-check=full`), and **Miri** on `cargo miri test` (`-Zmiri-tree-borrows -Zmiri-disable-isolation`) to catch UB/leaks in the unsafe FFI surface. Miri can't touch real sockets, so reactor tests are `#[cfg_attr(miri, ignore)]`.

### CI gates that fail the build (`.github/workflows/`)

- **ABI header** — `include/cares.h` (cbindgen-generated on every build from `src/`) must match `ci-data/cares.h.baseline`.
- **Exports** — the `.so`'s `ares_*` symbol set must match `ci-data/exports.baseline`.
- **Unsafe ratchet** — `python3 tools/unsafe_lines.py --check tools/unsafe_baseline.json`. The count of lines inside `unsafe` contexts may never grow past the baseline. If you legitimately move logic and the count drops, run `--update` to lower the ratchet; it must never rise.
- **Clippy `-D warnings`** — `cargo clippy --all-targets -- -D warnings`; this is also what makes the panic-safety deny wall in `src/lib.rs` binding.

When you change the FFI surface, regenerate and re-baseline: `cargo build`, then update `ci-data/cares.h.baseline` / `ci-data/exports.baseline` as part of the same change. The exports baseline is committed in **`LC_ALL=C` sort order** (and CI pins `LC_ALL=C` when comparing) — locale-dependent collation must never decide the gate.

## Architecture

The crate is split into three sections by hard boundaries, enforced by the compiler:

- **`src/async_runtime/`** — `#![forbid(unsafe_code)]`. Async IO + async/await execution, **nothing else**, in the shape of smol (async-io + async-executor) but driven by the caller's event loop: the `Socket`/`SocketFactory` traits (`socket.rs`); the per-channel reactor (`reactor.rs`) — `Reactor` (fd `Source`s with per-direction waker slabs + event ticks, a `(deadline, id) → Waker` timer map, the receive scratch), the `Ready` readiness future and `Timer`, both deregistering on `Drop`, and the `Runtime` handle (reactor + socket factory + detached-spawn queue; smol's implicit global made explicit) that core creates sockets/timers from and `spawn`s detached tasks on (≈ `tokio::spawn`: no output, never awaited; queued because the executor is mid-poll, and moved into it by ffi after the poll); where async-io blocks in `react()`, the host calls `Reactor::dispatch(now, skip_timeouts, ready)` per `ares_process*` turn and reads interest back via `interests()`/`next_deadline()`; `io.rs` — `Async` (async-io's `Async<T>` over a `Socket`: `readable()`/`writable()`/`read`/`readable_this_turn`) plus `send_when_writable`/`recv_datagram`/`recv_stream`; and the executor (`executor.rs`) — `Executor` (≈ `LocalExecutor`: reused slots of erased futures-with-a-delivery-closure (a task is moved out of its slot while polled, so re-entrant `spawn`/`deliver` are safe; a mid-poll cancel is deferred to the poll's end), one real `Waker` per task (`Arc<impl Wake>` + generation, so stale wakers can't poll a reused slot), a run queue popped by the host, `spawn`/`poll`/`pop_ready`/`deliver`). **Deviation from async-io:** I/O is attempted only *after* the caller reported readiness — caller-supplied sockets may block or return zero-length "datagrams". The runtime knows **bytes, not messages**: no framing, no demux, no pooling (that's protocol business logic — `core/conn.rs`). Imports **std + `futures-util`** (the `select_biased!` macro + `FutureExt` only) — nothing here names DNS, a wire format, or `crate::core` (grep-enforced wall). Wakers are real, so any std combinator works; the query engine still uses `select_biased!` where arm order matters (timeout-first recv, A/AAAA race).
- **`src/core/`** — `#![forbid(unsafe_code)]`. All resolver logic — DNS wire codec, system config, and the query lifecycles (self-contained async fns on `AsyncClient` driving `async_runtime` sockets) — as pure safe Rust behind pointer-free signatures. This is where behavior lives and where you make decisions.
- **`src/ffi/`** — every `unsafe` line in the crate. Marshals C arguments, implements the `Socket` traits over the C socket-function table, drives the reactor from `ares_process`, and *executes* the decisions core returns. Shims, builders, trampolines only — no policy. `src/lib.rs` sets `#![deny(unsafe_op_in_unsafe_fn)]` and re-exports `ffi::*` as the public API.

The refactoring goal is a shrinking unsafe surface: any logic found in `ffi/` should move into a `forbid(unsafe_code)` core function. The ratchet gate protects this.

### core module map

- `async_client.rs` — **THE resolver.** One struct, `AsyncClient`, is both the channel state (config/options/server list/shared pools — ffi's `ChannelData` wraps one instance; every config/lifecycle export is a method: `apply_options`/`saved_options`/`set_servers`/`duplicate`/…) and the resolver client: each entry shim mints a per-lookup copy via `derive()` (the same `rt: Runtime` handle, the same `shared: Rc<ChannelShared>` — health/cookies/cache/pools/qids/server-state hook, one `RefCell` each, also held by the probe, UDP lease and qid lease handles — and the channel's `servers: Rc<Vec<ServerId>>`, resolved once per server-list change by `servers_changed()`, which syncs per-server state to the new list like upstream `ares_servers_update`: a server still configured (same address and ports) keeps its health, cookie and pooled conns, removed ones lose them, duplicates are skipped, and a real change flushes the cache) and spawns one of the async lifecycle methods (`query_raw`/`gethostbyname`/`gethostbyaddr`/`getnameinfo`/`search`/`getaddrinfo`) — thin preflight + result-shaping shells. The two address lifecycles (`gethostbyname`/`getaddrinfo`) share the `resolve_addrinfo` DNS-phase core (search-name iteration + per-name `query_families` A/AAAA race with A-cancels-AAAA), mirroring upstream where `ares_gethostbyname` is a shell over `ares_getaddrinfo`; `gethostbyname` adds single-family Hostent pick + cache-store + sortlist. All ultimately drive the single-query `run_reserved_query()` (child module `async_client/request.rs`) — builds a `QueryState` (`create_query_state`), then loops `request`s over it (one `request` = one try over `async_runtime` conns: connect with failover, send once, listen; reply/send-failure/timeout/dead-socket handling inline, the failure kinds funnel into one shared failover tail). `request` takes `&QueryState` — it only reads the state, performs the channel side effects (health, server-state callback, pool eviction) and returns its decision as a `Next` (`Done` or `Retry { reached, change: Change }`); `run_reserved_query` is the **only** place that applies a `Change` to the query state; before the first `request`, `maybe_spawn_probe` may raise a failover probe (≈ upstream `ares_probe_failed_server`: 1/`retry_chance` draw, one in flight per server via `ServerHealth` `probing`) spawned via `Runtime::spawn` as its own detached task running `probe()` = one no-retry `request` pinned to that server (it applies the BADCOOKIE / FORMERR-strip / TC-upgrade re-sends itself); every query packet is a `ReservedQuery` — `reserve()` stamps a channel-unique transaction id from `qid.rs` (≈ upstream `generate_unique_qid`; the id is known before spawn, so the dnsrec shims report `*qid` synchronously, and it stays fixed across retries until the lease drops); A-cancels-AAAA travels as a shared `cancelled: &Cell<bool>`, server-state events straight to the application's callback (`notify` calls the ffi-installed `ServerStateHook` synchronously, mid-poll), and timeout counts in the lifecycle outputs. Split by function into child modules (each `use super::*`, so they share the private fields): `async_client.rs` itself = the struct, `derive`, shared types (`ServerStateHook`/`Delivery`/`HostReply`/`QueryOutcome`), `notify`, hosts-file helpers; `async_client/config.rs` = construction, `reinit`, defaults, `duplicate`, `apply_options`/`saved_options`, server-list exports (+ `DecodedOptions`/`SavedOptions`/`ServerSpec`); `async_client/packet.rs` = query builders (`build_query`/`dns_query_payload`/template rewrite/`frame_tcp`/`rdns_name`), `reserve`; `async_client/edns.rs` = EDNS(0) bound to the channel: OPT synthesis (`edns_udp_size`/`with_edns`) and the per-server cookie exchange (`with_cookie`/`apply_cookie`/`validate_cookie`) over `core::edns`'s codec + `ServerCookie` state machine; `async_client/lookups.rs` = `query_raw`/`gethostbyaddr`/`getnameinfo`/`search`/`search_dnsrec`/`search_plan` (+ `search_precheck`, `on_host_reply`); `async_client/addrinfo.rs` = `gethostbyname`/`getaddrinfo`/`resolve_addrinfo`/`query_families`; `async_client/request.rs` = the engine above plus probes and transport helpers (`connect_with_failover`, `calc_query_timeout`).
- `conn.rs` — the per-query connection facade over the runtime's byte arms: `Conn` (a shared-TCP or shared-UDP checkout, tokio-style `send`/`recv`) routing to the right transport; RAII slot release on drop. The pooling/mux machinery it drives lives in `tcp_pool.rs` / `udp_pool.rs`.
- `tcp_pool.rs` — DNS-over-TCP connection pooling: `TcpPool` (one shared conn per server — upstream behavior, pinned by the parallel-TCP gtest) + `TcpConn` (per-QID inbox demux, `recv_and_route` sibling-drain routing, `register_query` slots keyed by the channel-unique qid), plus the `dns_frame`/`dns_tag` codecs (RFC 1035 §4.2.2 length-prefix framing / transaction-id tags).
- `udp_pool.rs` — DNS-over-UDP connection pooling: `UdpPool` (per-server list of shared datagram conns, capped by `ARES_OPT_UDP_MAX_QUERIES` and pruned when `ARES_FLAG_STAYOPEN` is clear) + `UdpConn` (per-QID inbox demux over connected datagrams, same reroll/RAII shape as `TcpConn`).
- `nameinfo.rs` — getnameinfo's pure parts: `assemble_nameinfo` (NOFQDN, numeric fallback, LOOKUPSERVICE), `format_ip_with_scope`, `get_service_string`, `service_to_port`.
- `fds.rs` — the `ares_fds`/`ares_getsock`/`ares_timeout` tallies (`nfds`, `getsock_mask`, `clamp_timeout`).
- `qid.rs` — channel-wide transaction ids: `QidRegistry` (the in-flight id set), `QidLease` (RAII release), `ReservedQuery` (payload + lease).
- `lookup.rs` — the per-reply verdict logic: `on_datagram`/`on_timeout` (retry / failover / TC-retry decisions as pure functions), `summarize`/`qid_matches`, `SearchPlan` (ndots/bare-name iteration), `ServerHealth` (per-`ServerId` stats + the current order; lowest-failures-first selection, ties in config order), `ServerId` (a server's identity = address + UDP port + TCP port, as upstream `ares_server_find` matches; keys health, cookies and pools, and gives the connect/bind addresses), `is_localhost`/`is_onion_domain`.
- `hostent.rs` — `HostentBlueprint` (family/alias/addr decisions) + `addrttl_fill`.
- `dns_record.rs` — the record model (`ares_dns_record_t`/`ares_dns_rr_t`) + codec + metadata tables.
- `packets.rs` — DNS wire parsing (+ `AddrRecord`, `buf_to_ip`). `sortlist.rs`, `sysconfig.rs` (resolv.conf, `SysConfig`), `servers_csv.rs`, `hostfile.rs`, `services.rs`, `response.rs`, `cache.rs` — the rest of the pure surface.

### ffi module map

`mod.rs` holds typedefs/consts and re-exports. `lookups.rs` = entry shims (each marshals its C args, calls `state.derive()` + one lifecycle method, and `spawn`s the future with a one-line delivery closure) + the per-signature `on_*_reply` delivery handlers (`on_raw`/`on_dnsrec`/`on_hostent`/`on_nameinfo`/`on_addrinfo` — the only sites that call a C callback; each takes `Result<output, c_int>` = `Ok` on completion / `Err(status)` on cancel). `channel.rs` = `ChannelData` (= `AsyncClient` + the C callback fn-pointer fields + an `Executor`) + a thin orchestrator for the parts that can't cross the runtime wall: `spawn` (compose + first `advance`), `advance` (`executor.poll` → move `rt.take_spawned()` tasks into the executor as callback-less tasks → `executor.deliver(None)`), `turn` (`reactor.dispatch` with the caller's readiness, then `run_ready` pops woken tasks until the queue is empty or a per-turn budget is spent — leftovers make `ares_timeout` report 0), `drive_fd_futures` (`turn` with the `FD_ISSET` oracle — the sole unsafe), `abort_all` (`executor.deliver(id, Some(status))` + tcp-pool clear), `process_channel` + linked-list/fd_set marshal; it also owns the per-channel `ReentrantMutex` + `channel_access` that every API call takes. `event_thread.rs` = the opt-in `ARES_OPT_EVENT_THREAD` loop (≈ upstream `ares_event_thread.c` + `ares_event_wake_pipe.c`): `start`/`stop` (stored as `ChannelData::event: Option<EventThread>`), the `poll()` loop that snapshots `interests`/`next_deadline` under the lock and runs `process_events`, the `WakePipe`, and `ares_queue_wait_empty` (a blocking wait that only the event-thread model can satisfy — it never drives I/O itself); `evsys` is accepted but ignored (always `poll`). `process.rs` = the `ares_process`/`ares_process_fd` entry shims. `parsers.rs`, `addrinfo.rs`, `dns_record.rs` (57 shims), `convert.rs` (cstr/sockaddr), `ares_hostent.rs`/`ares_data.rs`/`ares_options.rs`/`ares_socket.rs` = marshalling + C-callback trampolines.

### Behavior notes

- **Socket-creation failure** (EMFILE/fd exhaustion) → `ARES_ECONNREFUSED`, never a panic. The socket factory returns `io::Result`; the connect-with-failover loops treat a creation failure like a dead server (fail over, or return `ECONNREFUSED` when the attempt budget is spent — matches upstream `ares_conn.c`). In `getaddrinfo`/`gethostbyname` each family (A/AAAA) is an independent `run_reserved_query` future (via `query_families`), so one family's `ECONNREFUSED` just means that family contributes no records; the other still delivers.
- **`ares_options` is the 1.34.6 layout** (152 bytes, includes `server_failover_opts` as a real field, accessed by direct field access — no offset arithmetic). Caller-allocated with the 1.34.6 header.
- **EDNS(0)**, **DNS cookies** (RFC 7873/9018 state machine) and **DNS 0x20** case randomization are implemented (`src/core/edns.rs` + the `request` engine). The **built-in event thread** is implemented (`ARES_OPT_EVENT_THREAD`, `ares_threadsafety()` = 1, recursive per-channel lock, wake pipe); the manual reactor API (`ares_fds`/`ares_process`/`ares_process_fd`) is retained. **No malloc-failure tests** — deliberate exclusion.
- RCODE map: 0=OK, 1=FORMERR, 2=SERVFAIL, 3=NOTFOUND, 4=NOTIMP, 5=REFUSED, 6+=ENODATA. RFC 6761 `localhost`/`*.localhost` → loopback. `.onion` rejected. Empty nameserver list → `ARES_ENOSERVER`.
- **Callback re-entrancy** (single thread per channel is assumed). Upstream documents no restriction on calling `ares_*` from any callback (its man pages only say the channel lock — a recursive mutex — is held), so re-entry is part of the drop-in contract. Status per callback (regression suite: `tests/reentrant_callback.rs`; probes for the rest were run 2026-11-09):
  - *Completion* callbacks: starting queries and `ares_cancel` are supported (upstream explicitly supports both).
  - *Server-state* callback: fires synchronously mid-poll (`ServerStateHook`); starting queries and `ares_cancel` are supported — `Executor::poll` moves the task onto the stack, so a re-entrant `spawn` may grow the slot table and a re-entrant `deliver` only records the cancel, applied when the poll returns (`server_state_callback_may_*`, ASan-verified). Upstream 1.34.6 would use-after-free on that cancel (from reading its source, not run): `process_timeouts`/`process_answer` keep using the query after the callback.
  - *Socket-state* and *socket-configure* callbacks: starting queries and `ares_cancel` are supported, including cancel when a socket closes (`sock_state_callback_may_cancel_on_tcp_close`). Upstream can use-after-free on that cancel when two or more idle conns are cleaned up (from reading its source, not run).
  - *Custom socket functions* (`ares_set_socket_functions*`): re-entry from every function works (probed, UDP + TCP, starting a query and `ares_cancel`). `arecvfrom` is the subtle one: `TcpConn`/`UdpConn::poll_read` take the conn's `&RefCell` and read the socket with it unborrowed, borrowing only to route (`arecvfrom_may_*`).
  - `pending_write_cb` is stored but never fired (writes are inline), so it cannot re-enter.
  - `ares_destroy` from any callback is **unsupported**: it frees the channel under frames still using it (upstream too). A query started from a callback that runs during `ares_destroy` is dropped without its callback.
  - Rules: never call into C — callbacks *or socket functions*, which run on read/send/close — while a `RefCell` borrow is live (hoist into a `let` first; never fire one from an `if let` whose scrutinee holds a `borrow_mut()`); methods that evict conns return them (`#[must_use]`) so the caller drops them after the borrow ends. Known formal caveat: any re-entry mints a second `&mut ChannelData` from the raw channel pointer while an outer frame is live — technically aliasing UB, benign in practice; the fix shape if ever needed is deferred callback firing.
- The C header is generated by `build.rs` via cbindgen into `include/cares.h` (git-ignored). `example.c` in `examples/` is the drop-in smoke test compiled in CI.
